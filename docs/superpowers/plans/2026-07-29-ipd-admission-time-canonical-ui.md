# IPD Admission Time and Canonical-Compatible Patient List Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Correct mixed legacy admission timestamp semantics without rewriting historical data, expose a canonical-compatible UTC API field, and make the IPD billing patient list readable on one line.

**Architecture:** Introduce a neutral admission-time normalizer consumed by legacy routes and canonical continuity. Legacy APIs expose `admitted_at_utc`; frontend renders that stable field in `Asia/Dhaka` and falls back to `admitted_date` during transition. New admission writes use explicit UTC ISO values so no new ambiguous rows are created.

**Tech Stack:** TypeScript, Hono, Cloudflare D1, React, Tailwind CSS, Vitest, Testing Library.

## Global Constraints

- Preserve legacy authority and non-blocking canonical shadow policy.
- Do not promote canonical reads or disable legacy tables.
- Do not rewrite historical production rows.
- Preserve `admitted_date` for backward compatibility.
- Canonical/provider timestamps must be explicit UTC ISO.
- Display timestamps in `Asia/Dhaka`.
- Keep name, age, and address on one non-wrapping line with identical typography.
- Do not touch unrelated dirty work.
