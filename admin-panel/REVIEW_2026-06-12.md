# Hospital Admin Panel — Full Review

**Review Date:** 2026-06-12
**Scope:** `/admin-panel/` (React 19 SPA) + `/src/routes/admin/` (Hono backend)
**Stack:** React 19 + Tailwind CSS v4 + React Router v7 + TanStack Query + Recharts + Lucide + Hono on Cloudflare Workers
**Base URL:** `/admin`
**Reviewer Verdict:** ⚠️ **NOT production-ready** — multiple critical security holes, dead code, and accessibility gaps. Functional UI but should not be exposed to super admin users in current state.

## 3. Critical Issues (Block Production)

### 3.1 🔴 Security: Unauthenticated PATCH endpoint
**File:** `src/routes/admin/index.ts:692`

```ts
adminRoutes.patch('/hospitals/:id/addons', async (c) => {
  // ⚠️ NO requireRole middleware!
  // ⚠️ NO JWT validation!
  const id = parseInt(c.req.param('id'), 10);
  if (isNaN(id) || id <= 0) {
    return c.json({ error: 'Invalid hospital ID' }, 400);
  }
  const { addons } = await c.req.json<{ addons: string[] }>();
  // ... updates tenants.addons without auth
});
```

**Impact:** Anyone on the internet can enable/disable any hospital's features (e.g., AI Summary) for any tenant by sending `PATCH /api/admin/hospitals/<id>/addons` with `{"addons":["ai-summary"]}`.

**Fix:** Add `requireRole(...SUPER_ADMIN_ROLES)` middleware and JWT validation.

### 3.2 🔴 Security: JWT in localStorage
**File:** `admin-panel/src/services/api.ts:4`, `hooks/useAuth.tsx:22-25, 58-60, 65`

JWT is stored in `localStorage` which is vulnerable to XSS. Any compromised script can read the super-admin token and exfiltrate it.

**Fix:** Move to `httpOnly`, `secure`, `sameSite=strict` cookies.

### 3.3 🔴 Dead code: Create Hospital modal
**File:** `admin-panel/src/pages/Hospitals.tsx:13, 66-72`

`showCreateModal` state and `setShowCreateModal(true)` button exist, but **no modal UI is rendered**. Clicking "Add Hospital" does nothing visible.

**Fix:** Implement the modal with form fields (name, subdomain, admin email/name, plan).

### 3.4 🔴 Dead code: Onboarding Provision modal
**File:** `admin-panel/src/pages/Onboarding.tsx:10, 33-44, 161-166`

`showProvisionModal`, `provisionMutation` (which actually calls `api.onboarding.provision`) exist, but **no modal UI is rendered**. The "Provision" button opens nothing.

**Fix:** Implement the provision modal form (slug, admin email/name, plan).

### 3.5 🔴 Fake Remote Control
**File:** `admin-panel/src/pages/RemoteControl.tsx:19-36`

The four "destructive" actions (maintenance mode, emergency shutdown, force password reset, revoke all sessions) **all just show a success toast** without calling any API. The page is misleadingly titled "Remote Control" but controls nothing.

**Fix:** Either wire to real API endpoints or clearly label as "Demo / Coming Soon" with disabled buttons.

### 3.6 🔴 No 404 / catch-all route
**File:** `admin-panel/src/App.tsx:33-55`

Unknown routes (e.g., `/admin/typo`, `/admin/foo`) render the Dashboard or nothing because the parent `/*` matches everything. Users get no feedback for invalid URLs.

**Fix:** Add `<Route path="*" element={<NotFound />} />` inside the protected layout.

### 3.7 🔴 Decorative Analytics date filter
**File:** `admin-panel/src/pages/Analytics.tsx:7, 9-12`

```tsx
const [dateRange, setDateRange] = useState('last30days');
const { data: stats, isLoading } = useQuery({
  queryKey: ['stats'],
  queryFn: () => api.stats.get(),  // ← dateRange NOT used
});
```

Selecting a date range does **nothing** — the API always returns the same data. The dropdown is purely cosmetic.

**Fix:** Pass `dateRange` to `api.stats.get(range)` and update the backend to accept and filter on it.

### 3.8 🔴 No CSRF protection
**File:** `src/routes/admin/index.ts` (all mutating routes)

All state-changing endpoints (POST/PUT/PATCH/DELETE) accept requests from any origin. Combined with JWT in localStorage, this is a cross-site forgery vector.

**Fix:** Add `Origin` header validation or CSRF tokens.

### 4.2 🟠 No 2FA / MFA for super admin

`POST /api/admin/login` (line 38) accepts only email + password. For a platform with full DB access, no second factor = unacceptable risk.

**Fix:** Require TOTP 2FA, hardware key, or at minimum email OTP for `super_admin` role.

### 4.3 🟠 No URL state sync
**Files:** `Hospitals.tsx:11-12`, `Users.tsx:8-9`, `AuditLogs.tsx:8-9`, `Onboarding.tsx:9`, `Analytics.tsx:7`

Page number, search query, and filters are in `useState` only. Refresh the page → state lost. Can't share deep links to "page 3 of search 'foo'".

**Fix:** Sync to `URLSearchParams` via `useSearchParams`.

### 4.4 🟠 No debounce on search inputs
**Files:** `Hospitals.tsx:62`, `Users.tsx:27`, `AuditLogs.tsx:27`

`onChange` triggers a new API call on every keystroke. Typing "hospital" = 8 requests.

**Fix:** 300ms debounce (e.g., `useDebounce` hook from `usehooks-ts`).

### 4.5 🟠 Heavy auth verification endpoint
**File:** `admin-panel/src/hooks/useAuth.tsx:38`

```tsx
const res = await fetch('/api/admin/stats', {  // ← runs 6 SQL queries!
  headers: { Authorization: `Bearer ${token}` },
});
```

Every page load runs the full stats query just to verify the token. The stats endpoint executes 6 parallel SQL queries against platform-wide tables.

**Fix:** Add lightweight `GET /api/admin/me` that returns user info from JWT.

### 4.6 🟠 No optimistic updates
**Files:** `Hospitals.tsx:48-51` (status toggle), `Onboarding.tsx:55-62` (approve/reject)

Mutations show stale UI for ~200-500ms before refetch resolves. For a status toggle, the UI should flip instantly.

**Fix:** Use TanStack Query's `onMutate` for optimistic updates.

### 4.7 🟠 Hardcoded production domain
**File:** `admin-panel/src/pages/HospitalDetail.tsx:146`

```tsx
<p className="text-slate-500 mt-1">
  {hospital.subdomain}.rahmatullahzisan.workers.dev
</p>
```

Hardcoded production domain. Will not work for `localhost` dev, will not work for staging, exposes real production URL in code.

**Fix:** Use `import.meta.env.VITE_APP_DOMAIN` or window.location.origin.

### 4.8 🟠 No global API error handling
**File:** `admin-panel/src/services/api.ts:20-28`

API client handles 401 by hard-redirecting, but other 4xx/5xx errors just throw a generic Error with no telemetry, no Sentry capture, no retry.

**Fix:** Add Sentry/Datadog hook, structured logging, retry with backoff for 5xx.

### 4.9 🟠 No session timeout warning
No warning when JWT is about to expire. User gets hard-redirected to login mid-action.

**Fix:** Show modal at T-5min, refresh token or prompt re-auth.

## 11. Recommendation

**Do not deploy the admin panel to production in its current state.** The unauthenticated PATCH endpoint is a critical security hole that any internet user can exploit. Additionally, the three dead-code features (Create Hospital, Onboarding Provision, Remote Control) and decorative date filter will mislead super-admin users into thinking features work when they don't.

**Estimated effort to production-ready:** 3–4 weeks (1 senior engineer, full-time).

**Minimum viable launch:** Complete Sprint 1 only (~1 week).
