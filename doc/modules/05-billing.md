> Reference documentation derived from the DanpheEMR .NET source tree at `DanpheEMR reference/Code/`.
> This document is intended as a self-contained reference of the legacy Billing module so that an
> agent can understand its scope, data model, API surface, and workflows without reading the
> source code.

---

## 1. Module Overview

The Billing module is the financial heart of DanpheEMR. It handles every aspect of charging
patients, collecting money, managing deposits, settling credit balances, generating tax-compliant
invoices, integrating with insurance schemes, and synchronising billing events to accounting
and external government/IRD systems.

**Core responsibilities:**

- **POS / Cash Counter billing** for OPD and IPD walk-in patients (`BillingTransaction`,
  `BillingTransactionItem`).
- **Requisition-based billing** for lab, radiology, OPD doctor visits, and other clinical
  services (`BillItemRequisition` -> lab/radiology tables).
- **Price-book and scheme management** (per-service-item price, scheme-aware discounts,
  credit limits, co-payment) — `BillingScheme`, `PriceCategory`, `BillMapPriceCategoryServiceItem`.
- **Patient deposits** (advance payments) with deposit-in, deposit-out, deposit-deduct and
  deposit-refund transactions (`BillingDepositModel`).
- **Settlement of credit bills** (corporate/insurance receivables) — `BillSettlementModel`.
- **Credit Notes / Invoice Returns** with `BillInvoiceReturnModel` and `BillInvoiceReturnItemsModel`.
- **IP (In-Patient) Billing** including bed charges, partial billing, estimation, and
  discharge bill.
- **Discharge Billing** that finalises the IP stay, calculates grand totals, and persists a
  `DischargeStatement` record.
- **Provisional Discharge** that releases the bed without finalising financials.
- **Insurance billing** (govt schemes, SSF, Medicare) with claim-code generation, balance
  tracking, and SSF/IRD real-time sync.
- **Cancellation of provisional items** (`BillingCancellationModel`).
- **Counter handover** (cash collection handover between billing staff) —
  `BillingHandoverTransactionModel`.
- **HIMS-Accounting sync** through `SyncBillingAccountingModel` and `BIL_SYNC_BillingAccounting`.
- **IRD/Government real-time sync** (`IRDLogModel`, `BillType=sales-return`, `sales`, etc.).
- **Reports** (daily collection, handover summary, transfer, estimation, etc.) via
  `SP_*` stored procs called from controllers.

**Billing philosophy:**

1. **Transaction vs Item split** — every receipt is a parent `BillingTransaction` with a
   child `BillingTransactionItem` per charged item. Aggregation (subtotal, discount, tax,
   total) happens at the transaction level; per-item math happens at the item level.
2. **Scheme-aware pricing** — the `BillingScheme` row is the master switch that decides
   whether a bill is cash/credit, whether discount/credit is allowed, what the default
   payment mode is, what credit limits apply, and which `PriceCategory` (rate card) is used.
3. **Counter as session** — every bill carries `CounterId` and `CreatedBy` (employeeId) so
   cash handovers and per-user cash tracking work.
4. **Fiscal-year aware numbering** — invoice numbers, settlement numbers, deposit receipt
   numbers, and credit-note numbers are all scoped to `BIL_CFG_FiscalYears` and
   incrementally generated by `max(value)+1`.
5. **Audit-friendly** — `BIL_TXN_BillingTransaction`, `BIL_TXN_Deposit`, `BIL_TXN_Settlements`,
   `BIL_TXN_InvoiceReturn` are all append-only ledgers; cancellations create a parallel
   record rather than mutating the original (except for status flags).
6. **Status state machine** — provisional → unpaid → paid / partially returned / returned.
   `BillStatus` is the canonical flag.

## 3. Data Models

## 5. Key Workflows

### 5.1 OPD billing (cash walk-in)

1. Reception/counter staff opens the billing page.
2. Backend loads the active `PriceCategory` list (`BIL_CFG_PriceCategory`), schemes
   (`BIL_CFG_Scheme`) for `serviceBillingContext=op-billing` via
   `BillingMasterController.Schemes`, and service items for the chosen price category
   via `BillingMasterController.ServiceItems`.
3. The user adds items to the bill. Each item resolves to a
   `BillMapPriceCategoryServiceItemModel` row to get the price, the scheme decides the
   default discount, default payment mode, and whether credit is allowed.
4. `POST /Billing/SaveBillingTransactionItems` (or `POST /Billing/PayProvisionalBills`) is
   called with a `BillingTransactionPostVM` payload (parent + child items + optional
   lab/radiology/visit requisitions to create).
5. Server: `BillingTransactionBL` writes `BIL_TXN_BillingTransaction` and
   `BIL_TXN_BillingTransactionItems`, updates or creates `BIL_BillItemRequisition` and the
   downstream `LAB_TestRequisition` / `RAD_PatientImagingRequisition` / `PAT_PatientVisits`
   rows, and stamps `InvoiceNo` / `InvoiceCode` / `FiscalYearId` for the current
   `BIL_CFG_FiscalYears`.
6. On payment, server inserts a row into `TXN_EmpCashTransaction` (`TransactionType=sale`)
   for the cashier's collection tracking.
7. If `realTimeRemoteSyncEnabled` is on (config), server fires an async `Task.Run(() =>
   BillingBL.SyncBillToRemoteServer(...))` to push to IRD (Nepal tax server) and SSF if
   applicable. The push logs to `IRD_Log`.
8. Server writes a `BIL_SYNC_BillingAccounting` row for each line item so the accounting
   job can pick it up and post vouchers.

### 5.2 IPD billing (partial bill during admission)

1. Nursing/admission selects the patient and visit; the bed is auto-billed by the
   `ADT_CFG_AutoBillingItem` config.
2. The user opens `IpBillingController` to add services (lab, radiology, consult, OT,
   consumables).
3. `GET /Billing/InpatientPendingBillItems?patientId=&ipVisitId=` returns un-billed items
   (from `BIL_BillItemRequisition`).
4. `PUT /Billing/PutIpBillingTxnItems` saves an IP partial transaction.
5. Bed quantity re-calculation: `PUT /Billing/ReCalculateBedQuantity?patientVisitId=`
   triggers `ADT_TXN_PatientBedInfo` math (start/end dates per bed-feature).
6. Estimation: `GET /Billing/EstimationBill?patientId=&ipVisitId=` returns a preview using
   current prices.

### 5.3 Discharge billing (final IP bill)

1. `POST /Billing/PostBillingAndPharmacyTransactionAndDischarge` is called with a
   `PendingBill` body (contains `IpBillingTxnVM` + `List<PharmacyPendingBillItem>`).
2. `DischargeBillingController.SaveBillingAndPharmacyTransactionAndDischarge` runs in a
   single `ReadUncommitted` transaction:
   1. Saves a new `BIL_TXN_DischargeStatement` row (`SaveDischargeStatement`).
   2. Saves the final `BIL_TXN_BillingTransaction` and items via
      `SaveBillingTransactionAndDischarge` (writes `DischargeStatementId` on each item).
   3. If zero items, calls `DischargeOnZeroItem` (releases the bed, no financials).
3. Real-time IRD push and SSF push (if SSF patient) run in background `Task.Run`.
4. `EMP_CashTransaction` is updated for the cashier.

### 5.4 Provisional Discharge (bed-only release)

1. `POST /Billing/Discharge` calls `IProvisionalDischargeService.PostProvisionalDischarge`.
   The bed is released and the visit is marked provisional-discharged. No final bill is
   created. All `BIL_TXN_BillingTransactionItems` for the visit get `IsProvisionalDischarge = true`.
2. Items are still billable later via `GET /Billing/ProvisionalDischargeItems` and
   `POST /Billing/PayProvisional` (which converts provisional items into a paid bill and
   sets `IsProvisionalDischargeCleared = true` on the parent transaction).
3. `PUT /Billing/DiscardAllItems` voids all provisional items (writes rows to
   `BIL_TXN_ProvisionalItemReturn`).

### 5.5 Deposit collection and use

1. `POST /Billing/NewDeposit` creates a new `BIL_TXN_Deposit` row with `TransactionType=deposit`,
   `InAmount`, `DepositBalance` (running sum). It also adds an `EmpCashTransaction` (`in`).
2. `DepositDeduct` (during settlement) writes a row with `OutAmount` and a `SettlementId` FK.
3. `ReturnDeposit` (refund) writes a row with `OutAmount` and `IsDepositRefundedUsingDepositReceiptNo`.
4. `GET /Billing/PatientDeposits?patientId=` returns a chronological list.
5. `GET /Billing/Deposits` lists all deposits (admin view).
6. `GET /Billing/GetOrganizationDeposits` lists organisation-held deposits.

### 5.6 Credit settlement

1. A credit invoice is created with `PaymentMode=credit` and `OrganizationId` set. The
   server also writes a `BIL_TXN_CreditBillStatus` row (`SettlementStatus=Pending`).
2. `GET /Billing/PendingSettlements?organizationId=` lists unsettled credit invoices
   via `SP_TXNS_BILL_SettlementSummary`.
3. `GET /Billing/PatientBillingInfo?patientId=&organizationId=` returns the patient's
   credit invoices, deposit info, and provisional totals (4-table result set).
4. `POST /Billing/NewSettlement` posts a `BillNewSettlement_DTO`:
   1. Inside a `ReadUncommitted` transaction, server creates a `BIL_TXN_Settlements` row.
   2. For each invoice in the settlement, updates `BIL_TXN_BillingTransaction.SettlementId`,
      `BillStatus=paid`, `PaidAmount`, `PaidDate`, `PaymentReceivedBy`, `PaidCounterId`.
   3. Updates each `BIL_TXN_BillingTransactionItems` to `BillStatus=paid` and sets
      `PaidDate`/`PaymentReceivedBy`/`PaidCounterId`.
   4. If `DepositDeducted > 0`, writes a `BIL_TXN_Deposit` row (`TransactionType=depositdeduct`)
      and an `EmpCashTransaction` (`out`).
   5. If `RefundableAmount > 0`, writes a `BIL_TXN_Deposit` row (`TransactionType=returnDeposit`)
      and an `EmpCashTransaction` (`out`).
   6. Updates `BIL_TXN_CreditBillStatus.SettlementId` and `SettlementStatus=Completed`.
   7. Updates `BIL_TXN_InvoiceReturn.SettlementId` for any credit notes included in the
      settlement (`BillReturnIdsCSV`).
   8. If `DiscountAmount > 0`, records an `EmpCashTransaction` for cash-discount given.
5. `GET /Billing/SettlementInfo?settlementId=` returns the receipt preview
   (`SP_Get_Settlement_Details_By_SettlementId`).

### 5.7 Credit note / Invoice return

1. `GET /Billing/InvoiceDetailsForCreditNote?invoiceNumber=&fiscalYearId=` returns patient,
   invoice, items, and already-returned items.
2. `POST /Billing/CreditNote` (form-encoded body, deserialised to
   `BillInvoiceReturnModel`) is called:
   1. Server validates with `IsBillReturnValid` (sum of `RetQuantity` across previous
      returns must not exceed the original quantity).
   2. If `DiscountReturnAmount > 0`, a new `BIL_TXN_Settlements` row is created first
      (`PaymentMode=cash`).
   3. New `BIL_TXN_InvoiceReturn` row with `CreditNoteNumber = max(per current FY) + 1`.
   4. Each returned line goes to `BIL_TXN_InvoiceReturnItems`.
   5. For each returned line, the downstream requisition's `BillingStatus` is set to
      `returned` (lab, radiology, or visit, based on `ServiceDepartment.IntegrationName`).
   6. If `IsInsuranceBilling`, calls `GovInsuranceBL.UpdateInsuranceCurrentBalance`
      (deducts from `PAT_PatientInsuranceInfo.CurrentBalance`).
   7. If `PaymentMode=credit`, calls `UpdateBillCreditStatusAndCreditBalance` which:
      - Adds `TotalAmount` to `BIL_TXN_CreditBillStatus.ReturnTotalBillAmount`.
      - Restores `PatientSchemeMap.OpCreditLimit` / `IpCreditLimit`.
      - If the scheme is Medicare (`ApiIntegrationName=Medicare`), adjusts
        `INS_MedicareMemberBalance.OpBalance` / `IpBalance` and reduces `OpUsedAmount`/`IpUsedAmount`.
   8. `UpdateEmpCashCollectionAmts` writes an `EmpCashTransaction` for cash refund.
   9. If `realTimeRemoteSyncEnabled`, async push to IRD with `BillType=sales-return`.
   10. If the patient is on SSF scheme (`PriceCategoryName=ssf`), async push to SSF with
       negative total amount.
3. `GET /Billing/CreditNoteInfo?creditNoteNum=&fiscalYearId=` returns the credit-note
   receipt.

### 5.8 Cancellation of provisional items

1. `PUT /Billing/CancelBillingTransactionItems` accepts cancellation of a provisional
   item (sets `BillStatus=cancel`, writes a `BIL_TXN_ProvisionalItemReturn` row).
2. `GET /Billing/BillCancellationReceipt?patientId=&provisionalReturnItemId=` returns
   the cancellation receipt.

### 5.9 Insurance billing

1. `BillInsuranceController.Get` with `reqType=insurance-patients-list` returns patients
   that have a `PAT_PatientInsuranceInfo` row.
2. `reqType=insurance-billing-items` returns items priced under
   `PriceCategoryId=1` (Normal — hardcoded, Krishna 13Mar'23).
3. `reqType=unclaimed-insurance-bills` returns bills where `IsInsuranceBilling=true`,
   `IsInsuranceClaimed=false`, `ReturnStatus=false`.
4. `reqType=insurance-packages` returns `BIL_CFG_Packages` with `InsuranceApplicable=true`.
5. When a bill is paid, if `SchemeId` belongs to a Medicare-`ApiIntegrationName` scheme
   and the patient is on the scheme, `MedicareMemberBalance.OpUsedAmount` /
   `IpUsedAmount` is increased by `bill.TotalAmount`.
6. SSF integration: `BillReturnController` posts to SSF server (via
   `BillingBL.SyncToSSFServer`) using `SSF_ClaimBookingService_DTO` with the latest
   `PatientSchemeMap.LatestClaimCode`.

### 5.10 Handover (cash collection transfer between counters)

1. `POST /Billing/PostHandoverTransactionDetail` writes a `BIL_TXN_CashHandover` row
   with `HandoverStatus=pending`.
2. `GET /Billing/GetPendingOutgoingHandOver?handOverType=` and
   `GetPendingIncomingUserHandOver` for the receiving employee.
3. `PUT /Billing/UpdateHandOverStatus?handOverTransactionId=` marks the handover as
   `received` (sets `ReceivedById`, `ReceivedOn`).
4. Reports: `GetHandoverReceiveReport`, `GetDailyCollectionVsHandoverReport`,
   `GetHandoverDetailReport`, `GetHandoverSummaryReport`,
   `TransferHandoverReport`.

### 5.11 Edit doctor / price / quantity

1. `GET /Billing/GetTxnItemsForEditDoctor?FromDate=&ToDate=&search=` (and the `_Rad`
   variant for radiology) returns a list of items the admin can edit.
2. `PUT /Billing/BillTxnItemDoctors?PrescriberObj=&PerformerObj=` updates prescriber
   and performer on items.
3. `PUT /Billing/UpdateDoctorafterDoctorEditRadiology` is the radiology-specific
   equivalent.
4. `PUT /Billing/EditItemPriceQtyDiscAndProvider` updates price/quantity/discount/provider
   on items (controlled by per-item `IsPriceChangeAllowed`).

### 5.12 HIMS-Accounting sync

1. After a bill is paid, server writes one `BIL_SYNC_BillingAccounting` row per line
   item (`TransactionType=sale`) and one per deposit (`TransactionType=deposit` or
   `depositDeduct` or `depositReturn`).
2. A separate scheduler (out of scope of this module) reads
   `IsTransferedToAcc = false`, posts vouchers via `ACC_Transactions` /
   `ACC_TransactionItems`, and sets `IsTransferedToAcc = true`.
3. Settlement creates `TransactionType=cashDiscountGiven` and
   `CollectionFromReceivable` rows in `TXN_EmpCashTransaction` plus
   `BIL_SYNC_BillingAccounting` for the discount amount.
4. Return of a settled bill creates a settlement row with `DiscountReturnAmount` which
   generates a `cashDiscountReceived` cash transaction.

## 8. Key Business Rules

### 8.1 `BillingSchemeModel` (`BIL_CFG_Scheme`)

A scheme (a.k.a. membership / plan) is the master switch. It determines pricing,
discounts, credit allowance, co-payment, and visit-compulsion rules for a patient.

| Field | Meaning |
|---|---|
| `SchemeId` | PK |
| `SchemeCode` / `SchemeName` / `Description` / `CommunityName` | Display |
| `ValidFromDate` / `ValidToDate` | Validity window |
| `IsMembershipApplicable` / `IsMemberNumberCompulsory` | Whether the patient must have a member number |
| `DefaultPaymentMode` | `cash` / `credit` / `cheque` |
| `IsCreditApplicable` | Whether credit is allowed at all for this scheme |
| `IsCreditOnlyScheme` | If true, every bill under this scheme is credit (no cash option) |
| `IsOpCreditLimited` / `IsIpCreditLimited` / `IsGeneralCreditLimited` | Per-bucket credit limit enforcement |
| `GeneralCreditLimit` / `OpCreditLimit` / `IpCreditLimit` | Limits (in NPR) |
| `IsRegistrationCreditApplicable` | Whether registration fee can be on credit |
| `IsOpBillCreditApplicable` / `IsIpBillCreditApplicable` | Per-context credit |
| `IsAdmissionCreditApplicable` | Whether admission deposit can be on credit |
| `IsOpPhrmCreditApplicable` / `IsIpPhrmCreditApplicable` | Pharmacy credit |
| `IsVisitCompulsoryInBilling` / `IsVisitCompulsoryInPharmacy` | Whether a visit must be opened before billing |
| `IsBillingCoPayment` / `IsPharmacyCoPayment` | Co-payment enabled |
| `BillCoPayCashPercent` / `BillCoPayCreditPercent` | Co-payment split for bills |
| `PharmacyCoPayCashPercent` / `PharmacyCoPayCreditPercent` | Co-payment split for pharmacy |
| `IsDiscountApplicable` / `DiscountPercent` / `IsDiscountEditable` | Global scheme discount |
| Per-context discount: `IsRegDiscountApplicable` + `RegDiscountPercent` + `IsRegDiscountEditable`, same for `OpBill`, `IpBill`, `Admission`, `OpPhrm`, `IpPhrm` | |
| `DefaultCreditOrganizationId` | Default org when credit is used |
| `DefaultPriceCategoryId` | Default rate card for the scheme |
| `ApiIntegrationName` | `Medicare`, `SSF`, etc. — triggers external sync |
| `FieldSettingParamName` | Legacy field-rendering hints |
| `IsSystemDefault` | Cannot be deleted if true |
| `RegStickerGroupCode` | Group code for registration sticker printing |
| `HasSubScheme` / `BillingSubSchemes` | Sub-schemes |
| `AllowProvisionalBilling` | If false, patient cannot have provisional bills |

The `BillingScheme_DTO` returned to the client only carries the columns that are
relevant to the current billing context (`OpBilling`, `IpBilling`, `OpPharmacy`,
`IpPharmacy`) — the controller / service maps the underlying table to the DTO based on
the `serviceBillingContext` query string.

### 8.2 Pricing and price category

- A `BillMapPriceCategoryServiceItemModel` row defines the price of a service item under
  a given `PriceCategoryId` (Normal, Foreigner, EHS, SAARCCitizen, SSF, GovtInsurance,
  etc.).
- `IsDiscountApplicable` on the map row controls whether per-item discount is allowed.
- `IsPriceChangeAllowed` controls whether a cashier can override the price at POS.
- `IsZeroPriceAllowed` controls whether `Price=0` is allowed (used for some govt schemes).
- `ItemLegalCode` / `ItemLegalName` are required for IRD-compliant invoices.
- `HasAdditionalBillingItems` flags items that auto-add related items (e.g. a surgical
  procedure auto-adds the OT charge). The additional items are defined in
  `BIL_CFG_AdditionalServiceItem` and picked up by `BIL_MST_ServiceItem` integration.

### 8.3 Discount

- Scheme-level `DiscountPercent` is the default.
- Per-item override via `BIL_MAP_ServiceItemSchemeSetting.DiscountPercent`.
- `IsDiscountEditable` controls UI override.
- `DiscountPercentAgg` on `BillingTransactionItemModel` is the cumulative discount
  (scheme + item-level). `DiscountAmount` is the per-row value.

### 8.4 Tax

- `IsTaxApplicable` on `BillServiceItemModel` and `IsTaxApplicable` on
  `BillMapPriceCategoryServiceItemModel` toggle tax for the item.
- Per-item `Tax` / `TaxPercent` (and aggregated `TaxTotal` / `TaxableAmount` /
  `NonTaxableAmount` on the parent) are sent to IRD for VAT reporting.
- `TaxableAmount` is the sum of `SubTotal - Discount` for taxable items.
- `NonTaxableAmount` is the sum for non-taxable items.

### 8.5 Co-payment

- A scheme with `IsBillingCoPayment = true` allows the bill to be split into a cash
  portion (`ReceivedAmount`) and a credit portion (`CoPaymentCreditAmount`).
- `BillingTransactionModel.IsCoPayment` is set when this happens.
- `BillingTransactionItemModel.CoPaymentCashAmount` and `CoPaymentCreditAmount` are
  per-item splits.
- The credit portion feeds `BillingTransactionCreditBillStatus.SalesTotalBillAmount`
  minus the `CoPayReceivedAmount`.

### 8.6 Credit organisations and credit limits

- A `CreditOrganization` (`BIL_MST_Credit_Organization`) is the corporate payer.
- `IsClaimManagementApplicable` toggles whether bills under this org go through
  `INS_TXN_InsuranceClaim` workflow.
- `IsClaimCodeCompulsory` / `IsClaimCodeAutoGenerate` control `ClaimCode` input.
- `PatientSchemeMap.OpCreditLimit` / `IpCreditLimit` are per-patient-per-scheme limits.
  On return of a credit bill, the limit is restored by
  `UpdateBillCreditStatusAndCreditBalance`.

### 8.7 Deposit

- A `BillingDepositModel` row is the source of truth for a patient's deposit balance.
- `InAmount` adds, `OutAmount` subtracts; `DepositBalance` is the cumulative running
  balance after this row.
- During a settlement, `DepositDeducted` creates a `depositdeduct` row.
- During a settlement refund, `RefundableAmount` creates a `returnDeposit` row.
- A patient can have many deposit heads (`BIL_MST_DepositHead`).

### 8.8 Status state machine

```
provisional -> unpaid -> paid
   |              |        |
   v              v        v
 cancel       returned   (return creates a credit note;
                          original txn gets ReturnStatus=true)
                          (partial return also creates a new
                           BillingTransaction with PartialReturnTxnId)
```

- `BillingTransactionModel.BillStatus`: `provisional`, `unpaid`, `paid`, `returned`, `cancel`.
- `BillingTransactionItemModel.BillStatus`: same set, with `OrderStatus` for nursing/doctor orders.
- `BillStatus` is set by `BillingTransactionBL.UpdateTxnItemBillStatus`.

### 8.9 Counter and per-employee cash tracking

- Every bill carries `CounterId` (where it was created) and `CreatedBy` (employee).
- On payment, an `EmpCashTransaction` row is added with `TransactionType=sale`,
  `InAmount=PaidAmount`, `EmployeeId=CreatedBy`, `CounterID=PaidCounterId`.
- On return of a paid bill, an `EmpCashTransaction` row is added with
  `TransactionType=SalesReturn`, `OutAmount=TotalAmount`.
- The cashier's daily collection = sum of `InAmount - OutAmount` for their employee id
  in a given day. The handover module uses this for shift-end reconciliation.

### 8.10 HIMS-Accounting sync rules

- One `BIL_SYNC_BillingAccounting` row per line item.
- `TransactionType` mirrors the cashier transaction: `sale`, `sales-return`,
  `deposit`, `deposit-return`, `deposit-deduct`, `cashDiscountGiven`,
  `cashDiscountReceived`, `CollectionFromReceivable`.
- `IncomeLedgerName` is the chart-of-account ledger (e.g. `Lab Income - OPD`,
  `Radiology Income - OPD`).
- `IsTransferedToAcc` is `null` / `false` until the accounting scheduler picks it up.
- `PaymentMode` is recorded so the accounting voucher can include the right sub-ledger
  (cash / bank / credit-org / deposit).

### 8.11 IRD / SSF real-time sync rules

- Configured via `MyConfiguration.RealTimeRemoteSyncEnabled` and
  `RealTimeSSFClaimBooking`.
- IRD push: `BillingBL.SyncBillToRemoteServer(billTxn, "sales" | "sales-return", dbContext)`.
  Runs on a `Task.Run` thread (fire-and-forget) to avoid blocking the request.
- All pushes are logged to `IRD_Log`.
- SSF push uses `SSF_ClaimBookingService_DTO` and is triggered only when the patient's
  price category is named `ssf`. Returns are pushed with negative amounts.

### 8.12 New billing structure (post-16Feb'23)

- Pricing is now keyed by `(ServiceItemId, PriceCategoryId)` rather than by
  per-department `BillItemPrice` rows. The legacy `BillItemPrice_Old_16thFeb_23` is
  preserved for migration.
- `BIL_MAP_PriceCategoryServiceItem` is the new authoritative price book.
- `BIL_MAP_PriceCategoryVsScheme` maps a scheme to its allowed price categories.
- `BIL_CFG_SubScheme` allows sub-grouping of a scheme.
- `SchemeId` was promoted onto `BillingTransactionModel` (per-invoice scheme).
- `PriceCategoryId` was promoted onto `BillingTransactionItemModel` (per-item).

### 8.13 Per-item accounting sync flags

- `BillInvoiceReturnItemsModel.IsCashBillSyncToAcc` / `IsCreditBillSyncToAcc` are
  per-line flags for the accounting sync, allowing partial sync of a returned invoice.

### 8.14 Hardcoded enums (used widely in code)

- `ENUM_BillingType`: `inpatient`, `outpatient`
- `ENUM_BillingStatus`: `provisional`, `unpaid`, `paid`, `returned`, `cancel`
- `ENUM_BillPaymentMode`: `cash`, `credit`, `cheque`, `deposit`, `card`
- `ENUM_DepositTransactionType`: `deposit`, `depositdeduct`, `depositReturn`, `depositRefund`
- `ENUM_EMP_CashTransactinType`: `sale`, `sales-return`, `deposit`, `depositReturn`, `depositDeduct`, `cashDiscountGiven`, `cashDiscountReceived`, `CollectionFromReceivable`
- `ENUM_ServiceBillingContext`: `OpBilling`, `IpBilling`, `OpPharmacy`, `IpPharmacy`
- `ENUM_VisitType`: `inpatient`, `outpatient`
- `ENUM_ClaimManagement_SettlementStatus`: `Pending`, `Completed`
- `ENUM_ModuleNames`: `Billing`, `Pharmacy`, `ADT`, `Inventory`
- `ENUM_Scheme_ApiIntegrationNames`: `Medicare`, `SSF`, etc.

### 8.15 Soft delete pattern

Most config tables use `IsActive` instead of hard delete. Transactions use `BillStatus`
flags. Returns don't delete the original — they create a credit note.

## 10. Migration / Modernisation Notes

For anyone rebuilding this module on a different stack (e.g. the in-progress
Cloudflare/Hono/D1 migration), the following points are critical:

1. **Preserve the transaction/item split.** Don't collapse the parent and child into a
   single table — the credit-bill status, claim, accounting sync, and credit-note flows
   all rely on it.
2. **Preserve the FY-scoped numbering.** `InvoiceNo`, `SettlementReceiptNo`,
   `CreditNoteNumber`, `DepositReceiptNo`, and `ClaimCode` are all `(FiscalYearId, max+1)`
   sequences. The migrations must guarantee uniqueness within FY.
3. **Scheme + PriceCategory are not the same thing.** A scheme (membership plan) decides
   pricing, discount, credit, and co-payment. A price category decides the rate card. A
   scheme has a default price category but can be used with others (when
   `BIL_MAP_PriceCategoryVsScheme` allows it).
4. **Status transitions are append-only.** Cancellation creates a parallel record in
   `BIL_TXN_ProvisionalItemReturn`. Return creates a credit note. The original
   `BIL_TXN_BillingTransaction` is not modified beyond a `BillStatus` flag and
   `ReturnStatus` / `PartialReturnTxnId` pointers.
5. **The IRD and SSF pushes are fire-and-forget.** They run on `Task.Run` and log to
   `IRD_Log`. The patient-facing request must not block on them. Make the same trade-off
   in the new system (use a queue or background worker).
6. **Co-payment splits are per-item, not per-bill.** `BillingTransactionItemModel` has
   `CoPaymentCashAmount` and `CoPaymentCreditAmount`. The parent
   `BillingTransactionModel.IsCoPayment` is a flag; the breakdown is on the items.
7. **The accounting sync is asynchronous.** `BIL_SYNC_BillingAccounting` rows are
   staging. A separate scheduler reads `IsTransferedToAcc = false`, posts vouchers, and
   flips the flag. Don't try to do this synchronously in the billing request.
8. **Deposit balance is a running sum.** Don't compute it on the fly; persist
   `DepositBalance` on each row for fast reads and audit.
9. **Counter handover is a separate workflow.** Don't merge it into `BIL_TXN_Deposit` or
   `BIL_TXN_BillingTransaction`; it has its own `BIL_TXN_CashHandover` table with
   `HandoverStatus`.
10. **Medicare / SSF integrations are scheme-driven.** The `BillingScheme.ApiIntegrationName`
    field is the trigger. `Medicare` adjusts `INS_MedicareMemberBalance` and the
    `PatientSchemeMap.OpCreditLimit` / `IpCreditLimit`. `SSF` triggers a real-time HTTP
    push. Other schemes are pure credit (no external integration).
11. **The new billing structure (post-16Feb'23) is the target.** When migrating, prefer
    `BIL_MAP_PriceCategoryServiceItem` over the legacy per-department `BillItemPrice`
    rows. `BillItemPrice_Old_16thFeb_23` is preserved only for migration.
12. **The `BillingTransactionCreditBillStatus` table is the source of truth for the
    corporate/insurance receivables ledger.** It is updated by `BillSettlementController`
    on settlement (`SettlementStatus=Completed`) and by `BillReturnController` on
    return (`ReturnTotalBillAmount` increases, `NetReceivableAmount` decreases).
13. **The `BillingController` monolith has 5,200+ LOC.** When refactoring, group the
    endpoints by domain (POS, requisition, edit, report, handover, IRD/SSF) and split
    them into smaller controllers.

## 12. Glossary

- **Scheme** — A membership / pricing plan that determines default payment mode,
  discount, credit, co-payment, and price category for a patient. E.g. `Normal`,
  `EHS`, `SAARC`, `GovtInsurance`, `Foreigner`, `SSF`, `Medicare`.
- **Price category** — A rate card. The same service item can have different prices in
  different price categories. E.g. `Normal`, `Foreigner`, `EHS`, `SAARCCitizen`,
  `SSF`, `GovtInsurance`.
- **Counter** — A physical or virtual billing counter. Each bill is associated with a
  counter; cash collection and handovers are per-counter.
- **Provisional** — A bill that has not been paid. Items are recorded but the
  transaction is not finalised. Becomes `paid` when the patient pays.
- **Credit organisation** — A corporate entity that pays on behalf of the patient.
  E.g. `Nabil Bank`, `SSF`, `Beema Samiti`.
- **Credit bill** — A bill paid by a credit organisation rather than the patient. Tracks
  via `BIL_TXN_CreditBillStatus`. Settled via `BIL_TXN_Settlements`.
- **Settlement** — A periodic payment from a credit organisation against all its
  outstanding credit bills. Generates a settlement receipt and updates
  `BIL_TXN_CreditBillStatus.SettlementStatus` to `Completed`.
- **Credit note** — A reversal of an invoice. Creates `BIL_TXN_InvoiceReturn` and
  `BIL_TXN_InvoiceReturnItems` rows; updates `BIL_TXN_BillingTransaction.ReturnStatus`.
- **Co-payment** — A bill where the patient pays part (cash) and the credit organisation
  pays the rest. E.g. patient pays 10% cash, 90% credit.
- **Deposit** — A pre-payment held on the patient's account. Used to settle future
  bills. `BIL_TXN_Deposit` is the ledger.
- **Handover** — Transfer of cash collection from one cashier to another (or to
  accounts). `BIL_TXN_CashHandover`.
- **IRD** — Nepal's Inland Revenue Department. Bills are pushed in real-time for VAT
  reporting. Push goes to `BIL_SYNC_BillingAccounting` and out to the IRD HTTP API.
- **SSF** — Social Security Fund. A specific credit organisation that requires a
  claim code and accepts real-time claims via HTTP API.
- **Medicare** — A US-style insurance scheme integration. Tracks per-member balance
  via `INS_MedicareMemberBalance`.
- **Insurance billing** — A bill flagged `IsInsuranceBilling=true`, with an
  `InsuranceProviderId`. Generates a `ClaimCode` and feeds the claim-management
  workflow.
